# 与《装机模拟器 1／2》的覆盖、细节及功能差距

核对日期：2026-11-08；对应 0.45 源码候选。本文是待办与验收边界，不是“已经达到装机模拟器”的声明。

用户要求先完善现有硬件、配件类别和六版表现，再考虑新外观。本轮固定保留 **1 原版、2 可爱笑脸、3 彩色手绘、4 纯线条、5 奶油贴纸、6 拼色剪纸**；已有 13 个运行时保存值全部保留，不新增风格，也不把多种风格重复计为产品。原版没有笑脸。

“先六版全类别补齐／盘点”要按 CPU、GPU、内存、主板、机箱、风冷、AIO、独立冷排、风扇、电源、存储、扩展卡，以及仍缺的零售水路部件和外设逐类核对。不能某一版缺型号、少风扇或用通用图替换，就以其它版已经有为由算完成；也不能把“13 个选项能生成”当成每款六版均已亲看。尚无目录的类别在六版都仍缺，未核资料在各版同样保留未知。本轮先列问题、补结构和验证，不启动新的外观方案。

目前距离“所有品牌、系列、配件类别都完整，细节达到或超过 PCBS 1／2”仍有明显差距。优先事项是零售水冷部件缺类、安装与接口证据、尚未核实的型号细节，以及桌面实际验收。增加目录条目不能替代这些工作。

### 名称比较已发现的问题

- SSD、CPU Blocks、Other 原先会继承前一类别，导致标题算成产品、存储混入外设、冷头混入内存、桥接件混入存储；本轮已修正分类并删除这三个标题条目。
- 同一 ID 的别名只算一个候选；不同 ID 规范名称相同则保持待核，不能随便挑一个。公告本身的拼写差异、品牌省略和系列泛称仍需人工核对，不能静默改成现实 SKU。
- `|`／“Includes”组合不展开为多个“已核产品”；正文中的 Bug Fixes、Bug List、Quality of Life 等段落不能混入配件清单。
- 261 是保留来源的**列表出现次数**，不是已经人工核过的独立 SKU 数。当前六个来源未检出同类别、规范名称完全相同的重复行，但别名、系列泛称与合并变体仍未逐个排除；后续补公告也要重新查重和人工分类。

对应定向回归：[test_pcbs_comparison045.py](../tests/test_pcbs_comparison045.py)。这些合成 HTML 测试验证比较规则，不证明发行方网页以后永远使用同一排版。

## 接下来的完成顺序与逐项验收门槛

1. **先闭环当前六版和已有型号。** 修真实外形、叶轮、薄厚、接口、静止遮挡及各版一致性；把未核部分明确列出，不能换成泛用外形就说完成。保留 13 个保存选项和原版无表情，本轮不增新风格。
2. **补缺类而不只补数量。** 优先独立零售冷头、泵、水箱、接头和原厂扣具，再处理平台／板型稀疏区域、外设及其它已确认缺失的品牌系列。每批都有 exact ID、主源、已核／参考字段和实际选择后的模型，不靠颜色或瓦数凑独立结构数。
3. **验证真实装配关系。** 补尺寸与安装面来源、孔径／间隙、接头与管路、线缆、厚度堆叠；错误选择要完整拒绝或明确参考，不能留下看起来接通的半成品。
4. **再完成按需分发与资源检查。** 每个包可独立加载、卸载失效、恢复选择；关闭视图释放资源，切风格复用几何，不引入额外硬件轮询、独立时钟或常驻后台任务。
5. **最后逐条原生验收和汇报。** 在用户方便时验证屏幕二、游戏隐藏、CPU 每次启动授权／温度、顶部栏／设置／详情磨砂、崩溃恢复和本机 CPU／内存／GPU 开销；当前仍在游戏，不安装、不重启或弹窗。CPU／GPU 模型小组件及硬件 Top 5 的未完成项继续按 [README 全文需求表](../README.md#全文需求逐项核对与未完成清单)与[结构化需求](REQUIREMENTS.json)单独跟踪。

“先全部完善再新外观”是顺序约束，**不是本轮已完成全部的声明**。只有逐项来源、模型、交互、软件验证、原生验证及剩余问题都可复查，才可把对应项从部分完成改为完成。PCBS 级整体覆盖与细节目前仍记为**尚未达到**。
